# REVIEW.md

Defects in the starter app/main.py, then defects I found later in my own Phase 2 code, then things I checked and decided were fine. Rule numbers (R1-R10) are from openapi.yaml.

**How to read the "fixed" column.** *Tests ran* means the named tests executed and passed. The 1038 mock-based tests use
`mongomock`; the 62 real-MongoDB tests passed in GitHub Actions on MongoDB 7.0 and 6.0 (section H). The Phase 4 pipelines are
also checked by a test-only interpreter (section F).

I reproduced the helper and model defects by running the original starter code; the "notice" column quotes what it returned.

## C. Looked at and decided these are not defects

* IST = timezone(timedelta(hours=5, minutes=30)): correct, and India has no daylight saving time.
* load_dotenv() with its default override=False: a real environment variable wins over .env, which is what the README promises.
* compute_work_hours argument order and the / 3600 conversion: right; only the rounding was wrong (#4).
* GET /attendance?page=1.0 and ?page=+1 are accepted as page 1 (FastAPI's lenient integer parsing). 1.5, abc, 0 and 1e2 are 422. The contract only says page is an integer >= 1, so I left this alone.
* A repeated query parameter (?emp_code=A&emp_code=B) uses the last value; harmless.
* total computed by a separate count_documents: it can differ from the page by one if a write lands between the two calls. Acceptable for a list endpoint.
* A punch-in is not rejected for a time before joined_on or in the future: the contract does not say so, so I did not invent a rule.

## E. Phase 3 (punch-out and PATCH): defects found in my own first draft

| # | Where | What was wrong | How I found it | How it was fixed |
|---|---|---|---|---|
| 33 | first draft of both writes | Used find_one_and_update(..., return_document=AFTER) and treated None as "lost the race". mongomock implements AFTER by re-running the original filter after the update, and my compare-and-set filter names the fields the update changes (punch_out: null, the old punch_in), so it matched nothing and returned None although the write had happened. Real MongoDB returns the post-image atomically and would not do this; the code should not depend on which one it is. | A smoke test on the sample data: the open sample record "failed" to punch out while punch_out was in fact set. Tests ran (the whole Phase 3 suite). |
| 34 | tests/ design | A threaded "N simultaneous requests" test of an update against mongomock would prove nothing: mongomock has no locking, so two writers can both match. | Read mongomock's collection.py (no locks). | Mocked concurrency tests are deterministic interleavings (RacingCollection): a rival write lands between the endpoint's read and write. | 35 | validation_failed docstring (present since Phase 2, found when Phase 3 was reviewed) | The docstring contained the text \ud800 written with a single backslash. My own Phase 3 docstring on _check_storable_text already used a doubled backslash; this older one was missed. | Reported by the reviewer. Sensitivity check: nine deliberate breakages of the punch-out / PATCH logic (dropping a compare-and-set condition, choosing the oldest record, overwriting instead of appending history, removing the no-op check, and similar) each made the suite fail.

Known weakness: the history-length part of the PATCH guard cannot be exercised through the API on its own, because every valid correction also changes status, punch_in or punch_out, which the guard already pins. It is kept for the case where a record returns to an earlier state (A to B to A) while we were deciding. It is covered by a unit test of the guard only, not by an end-to-end test.

## G. Earlier verification pass (2026-10-12, before CI had run)

No application code was changed in this pass. What was done and what it shows:

* Baseline reproduced: full suite on the extracted project, 1038 passed, 62 skipped, 0 failed (mock-based; see README).
* Real startup without MongoDB: uvicorn app.main:app was started against an unreachable MongoDB. It starts, logs that indexes could not be verified, /health and the database endpoints answer 503 {"detail": ...}, and /openapi.json answers 200.
* Real MongoDB 6.0+ could not be obtained there: fastdl.mongodb.org and repo.mongodb.org do not resolve, there is no MongoDB package in the Ubuntu 24.04 archive, no PyPI/npm package bundles a mongod (the npm/PyPI helpers download from the blocked host), there is no Docker, and a source build needs far more memory/disk than the 1-CPU, 3 GB machine had.
* Partial run on FerretDB 1.24.0 (SQLite backend), which is not MongoDB. It reports itself as 7.0.42, so the version test passes, which proves nothing. Of the 62 integration tests, 21 passed in the final run and 41 failed. The failures I inspected come from FerretDB, not from the app: partial / sparse / collation index options "not implemented"; no explain executionStats or winningPlan; the aggregation stages $setWindowFields/$densify are the analytics pipelines' core and are not supported; explain rejects an int skip. The concurrency results were non-deterministic. A probe with no application code at all (two threads, update_one({"_id": 1, "v": 0}, {"$set": {"v": 1}})) let both writers match in 59 of 60 trials, where MongoDB guarantees at most one. So FerretDB cannot confirm or refute the compare-and-set and concurrent-create behaviour either. The tests that passed there (index creation and idempotence, unique-index enforcement, create / punch-in / list end to end on real BSON, the lone-surrogate 422) are mildly reassuring about PyMongo and BSON handling, nothing more.
* Still unverified on a real MongoDB 6.0+ at that time (unchanged from sections E and F): concurrency guarantees, the four analytics pipelines, the semantic assumptions about $rank, $densify and window frames, and the IXSCAN / no-COLLSCAN explain plans. .github/workflows/tests.yml was added so that these can be run on MongoDB 6.0 and 7.0 without a local server; it had not been run yet. Superseded by section H.
* requirements.txt: pymongo[srv] became pymongo>=4.7 plus dnspython>=2.0 (current PyMongo has no srv extra and printed a warning; dnspython is still needed for mongodb+srv:// URIs).
